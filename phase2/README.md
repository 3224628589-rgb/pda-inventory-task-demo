## 演示路径

我的 → 盘点 → 盘点任务 → 第一张任务卡。

1. **数量**：初盘暗盘，不显示盘前数量，盘后数量默认留空。录入整数后点“下一步”。
2. **追溯码**：逐盒扫码，数量须等于盘后数量。提供输入/录入、删除和返回；下方“演示扫码”可逐个添加本批次或其他批次的模拟追溯码。目标为0时不需扫码，仍可进入结果页。
3. **结果**：首次揭示盘前数量与盈亏。若扫描到当前商品的其他批次，按批号和有效期列出待下架清单；否则展示“无需取货下架”。点击“下一个”才记为已盘，继续同货位或下一货位。

可输入数量3，点击两次“本批次 +1”和一次“其他批次 +1”，体验待下架结果。

## 边界与状态

- 返回修改数量保留扫码草稿；减小数量后，必须手动删除多余码。
- 同一任务中已确认和其他草稿中的追溯码均不能重复录入。
- 20位数字校验、未收录码及商品不匹配会提示；扫码数量不足或过多不能进入结果。
- 未到第三步并点击“下一个”的明细仍是未完成，不能提交任务。
- 刷新保留数量、步骤和扫码记录。重新盘点清理该明细的上一轮扫码结果。
- 复盘、临时盘点和原有搜索、排序、提交等流程沿用一期。
- 二期独立使用 sessionStorage 的 pda-inventory-phase2-v1 与 pda-phase2-task-tab；一期的数据不受影响。

## 模拟口径

这是交互 Demo，未连接真实追溯码解析平台。录入只识别本地演示目录中的码；“演示扫码”创建20位合成码并绑定当前商品、批号和有效期，不从真实码字符猜测批号。真实门店样本的商品照片沿用一期，但追溯码仍是合成数据。

按截图解释为：盘后数量是本轮实际扫描数量，待下架是后续操作提示，不在浏览器中声称完成真实库存调账。结果的盈亏按盘后减盘前计算；截图中的个别不一致公式未照搬。
