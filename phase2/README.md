## 演示路径

我的 → 盘点 → 盘点任务 → 第一张任务卡。

1. **数量**：初盘暗盘，盘后数量默认留空。录入整数后点“下一步”。
2. **追溯码**：输入框数量等于盘后数量。默认定位首个不足20位的输入框；录满20位自动定位下一未满行。全部留空代表实物无追溯码，部分填写会拦截。
3. **结果**：不显示盘前数量及盈亏。所有码属于当前批号或没有录码时，固定显示“无需取货下架，点击下一个完成盘点”；出现其他批号时，按批号分组列出待下架数量与追溯码。点击“下一个”才计入已盘。

体验混合批次：录入数量3，依次点击三个输入框，再进入结果。每第3行的模拟码归属其他批次，其余归属当前批次；这是固定演示样本。

## 按 PRD 实现的规则

- 点击任意输入框立即模拟一次完整20位扫码。输入框不弹软键盘；自动聚焦不触发扫码。
- 右侧清空只清内容，保留输入框数量。
- 当前商品批次明细内去重。扫码重复不写入并提示“请勿录入相同追溯码”。
- 扫描非20位数字时拒绝写入并提示“请扫描追溯码录入”；成功扫描覆盖当前输入框。
- 未全部录完且不全为空时，提示“若实物有追溯码，请录全追溯码，若实物无追溯码，请留空，不可录入部分追溯码”。
- 查询中或核准失败不能进入结果；可点击该输入框重新扫描，或清空。
- 有追溯码时，当前批号核准数量x1作为该明细盘后数量，差异=x1-盘前Y；其他批号数量不计入当前批号库存。
- 无追溯码时，按第一步录入数量盘点。录入数量与核准数量分别保存。
- 返回修改数量保留已有草稿；减少数量涉及非空末尾行时，需要确认清除。
- 刷新保留步骤、逐行输入与核准结果；旧版扫码草稿兼容迁移。旧版已确认记录按新口径更新当前批号数量。
- 大数量采用虚拟列表显示所有逻辑输入行，避免一次创建大量页面元素。
- 复盘、临时盘点以及菜单、搜索、排序、提交保持原有交互。
- 二期独立使用 sessionStorage 的 pda-inventory-phase2-v1 与 pda-phase2-task-tab；一期数据不受影响。

## 模拟边界

未对接真实“码上放心”或原生PDA扫码硬件。点击输入框创建合成码并绑定演示商品批次，调用本地模拟核准逻辑；未收录的码核准失败，不根据真实码字符猜批号。保留 `pda-trace-scan` 事件，detail 包含 code 及可选的零起始 index。

扫码卡不添加进度、规则说明、扫码入口或演示按钮。输入行28px、间距7px、左右箭头57×105px，图标直接使用指定 Figma 节点导出的SVG；数字及箭头文字使用对应字体子集。下一步内容向右滑动320ms，上一步反向，系统减少动态效果时即时切换。动画期间拦截重复点击。

照片沿用一期本地商品图。页面不执行真实库存调账或取货下架。
